# FileShare

FileShare — сервис обмена файлами через приватные Telegram-каналы. Он создаёт публичные ссылки с необязательным паролем, сроком действия и лимитом скачиваний.

## Возможности

- Потоковая загрузка и скачивание файлов до 2 ГБ через локальный Telegram Bot API.
- Новые файлы шифруются на сервере до отправки в хранилище; старые файлы продолжают работать в режиме совместимости.
- По желанию файл шифруется в браузере сквозным шифрованием; ключ не отправляется серверу и находится только во фрагменте ссылки.
- Пароли на `scrypt`, короткоживущие HttpOnly download-grant cookies и атомарные лимиты скачиваний.
- Публичная загрузка с мягкими ограничениями: до 3 параллельных загрузок, 30 файлов в час и 100 ГБ в сутки с одного IP.
- Ежечасная очистка истёкших ссылок: Telegram-сообщение и метаданные SQLite удаляются вместе.
- Несколько Telegram-ботов: новый файл назначается на наименее загруженный активный аккаунт.

## Production: Docker на VPS

Нужны Docker Compose, домен и TLS-сертификаты `fullchain.pem` и `privkey.pem` в папке `certs/`. Внешне доступны только порты 80 и 443 Nginx; приложение, SQLite и локальный Bot API не публикуют порты на хост.

1. Скопируйте `.env.example` в `.env`, заполните случайные `DOWNLOAD_GRANT_SECRET` / `CLEANUP_KEY` / `FILE_ENCRYPTION_KEY`, SMTP-параметры и `TELEGRAM_API_ID` / `TELEGRAM_API_HASH`.
2. Поместите TLS-сертификаты в `certs/fullchain.pem` и `certs/privkey.pem`.
3. Запустите `docker compose up --build -d`. При первой сборке Docker компилирует официальный локальный Telegram Bot API, поэтому она занимает заметное время.
4. Откройте `/register` и зарегистрируйте первого пользователя — он автоматически получает роль администратора. Войдите в `/admin`, добавьте бота в приватный канал как администратора с правами публикации и удаления сообщений, затем добавьте его в панель.
5. Один раз проверьте очистку без удаления:

   ```bash
   docker compose exec app node -e "fetch('http://localhost:3000/api/internal/cleanup?dryRun=1',{method:'POST',headers:{Authorization:'Bearer '+process.env.CLEANUP_KEY}}).then(r=>r.text()).then(console.log)"
   ```

Локальный Telegram Bot API запускается в `--local` режиме. Перед его использованием выйдите ботом из облачного API, вызвав `logOut` по инструкции Telegram. Без `TELEGRAM_API_BASE` сервис намеренно ограничивает файлы 50 МБ.

На Windows при пути к проекту с кириллицей BuildKit некоторых версий Docker может завершиться ошибкой кодировки контекста. В этом случае однократно выполните в PowerShell:

```powershell
$env:DOCKER_BUILDKIT = "0"
docker compose up --build -d
```

Либо перенесите рабочую копию в путь из ASCII-символов. На VPS эта особенность обычно не возникает.

Для резервного копирования сохраняйте Docker volume `app_data` вместе с файлами SQLite WAL (`filesshare.db`, `filesshare.db-wal`, `filesshare.db-shm`). Делайте snapshot после остановки приложения либо через резервное копирование уровня volume.

## Локальная разработка

```bash
npm install
cp .env.example .env
npm run dev
```

Без локального Telegram Bot API лимит загрузки равен 50 МБ. Для production обязательны `DOWNLOAD_GRANT_SECRET`, `CLEANUP_KEY`, `FILE_ENCRYPTION_KEY`, `SMTP_HOST` и `SMTP_FROM`. Пользователи и их роли хранятся в SQLite; первый зарегистрированный пользователь становится администратором.

`FILE_ENCRYPTION_KEY` — секретный 32-байтовый ключ в формате base64url. Он не должен попадать в Git и должен сохраняться вместе с резервной копией базы данных: без него новые зашифрованные файлы восстановить невозможно. Поле `content_encryption` отделено от `storage_encryption`, поэтому серверный слой и сквозное шифрование работают совместно.

Сквозное шифрование включается в настройках загрузки. Ключ находится после `#` в ссылке и не передается HTTP-запросами серверу. Если ссылка без ключа или ключ потерян, файл невозможно расшифровать. Для больших E2EE-файлов браузер должен поддерживать File System Access API (Chrome/Edge); в остальных браузерах используется fallback для файлов до 512 МБ.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/upload` | Потоковая загрузка multipart-файла |
| `GET` | `/api/files/:token` | Публичные метаданные файла |
| `POST` | `/api/files/:token/access` | Проверка пароля и выдача короткой download-cookie |
| `GET` | `/api/download/:token` | Потоковое скачивание; пароль не передаётся в URL |
| `POST` | `/api/auth/register` | Регистрация пользователя |
| `POST` | `/api/auth/login` | Вход и создание HttpOnly-сессии |
| `POST` | `/api/auth/logout` | Выход и удаление сессии |
| `POST` | `/api/auth/forgot-password` | Запрос ссылки восстановления пароля |
| `POST` | `/api/auth/reset-password` | Установка нового пароля по одноразовому токену |
| `GET/POST/PATCH/DELETE` | `/api/admin/accounts` | Управление Telegram-аккаунтами для пользователей с ролью `admin` |
| `GET/POST` | `/api/admin/encryption` | Статус и партия перешифрования старых файлов для `admin` |

Пароль для скачивания принимается только маршрутом `/access`; query-параметр `password` и заголовок `x-file-password` больше не поддерживаются.
